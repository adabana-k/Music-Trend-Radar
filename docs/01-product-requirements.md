# 01 製品要求仕様（PRD）

## 1. ゴールとスコープ
**課題:** すでに人気の曲だけでなく、ListenBrainzの聴取活動で増加が始まった曲・アーティストを素早く発見したい。

**MVP:** 個人用・非公開のWebダッシュボード。ListenBrainzサイト全体の**確定した週間集計**で人気/急上昇を表示。MusicBrainzメタデータで識別を補完。週次更新、言語は日本語、表示時刻はAsia/Tokyo（計測窓はUTC）。対象は**世界のListenBrainz利用者**。JP市場指定はMVPでは提供しない。

## 2. ユーザーストーリーと機能
| ID | 要件 | 優先度 | 完了条件 |
|---|---|---|---|
| FR-01 | ListenBrainz `sitewide` の人気楽曲・アーティストを定期取得 | MUST | APIから1回取得、レスポンスの期間・更新時刻・取得時刻を記録 |
| FR-02 | 週間人気楽曲ランキング | MUST | `listen_count` 降順、ソース・期間・更新時刻を表示 |
| FR-03 | 週間急上昇ランキング | MUST | **比較可能な非重複の確定週**が2期間以上ある場合のみ増加率・差分を表示 |
| FR-04 | アーティストランキング/詳細 | MUST | アーティストのsitewide統計をそのまま利用。曲の合計を安易に代替しない |
| FR-05 | 楽曲詳細 | MUST | 観測週ごとの聴取回数、変化率、同一性の確度、欠損状態 |
| FR-06 | データ品質/鮮度 | MUST | 未確定週、更新遅延、上位N打ち切り、同定不能を表示 |
| FR-07 | 名称検索 | SHOULD | 保存済み楽曲・アーティストを部分一致で検索 |
| FR-08 | MusicBrainz連携 | SHOULD | MBID有なら付与、無ければ未同定として表示（強制マージしない） |
| FR-09 | Geminiの根拠付き説明 | SHOULD | 集計値のみを渡し、モデルはランキング決定に関与しない |
| FR-10 | CSVエクスポート | COULD | 集計値のみ、出典・期間・定義を付与し管理画面の設定で制御 |
| FR-11 | ListenBrainz公開ダンプ取込 | LATER | 設計/コスト/プライバシー審査後、重複・削除・増分を検証 |
| FR-12 | 将来の上位入り予測 | LATER | 過去データでリークのないバックテストを通過してから有効化 |

## 3. 重要なユースケース
US-01: 今週のListenBrainz人気上位曲を知る。US-02: 先週と比較して伸びた曲を知る。US-03: 同じ曲名の別録音を区別できる。US-04: 急上昇の根拠とデータの偏りを理解できる。US-05: AIの説明に数字の出典が付く。

## 4. 非機能要件
- APIのp95応答時間の目標2秒（マート読取時、コールドスタート除外の観測目標）。
- 冪等取込：同じ期間/同じ版のスナップショットの再実行で集計行を重複させない。
- 本番は認証付き、Secrets不記録。BigQueryクエリ費用・LLM利用回数に上限。
- DBにない値を補間せず、ランキング対象外を「再生ゼロ」と断定しない。
- 全集計レスポンスに`source_id`, `period_start`, `period_end`, `source_updated_at`, `fetched_at`, `coverage_note`を含む。

## 5. 非対象
Spotify API、音源ファイル取得、全世界/日本のSpotify再生市場推計、勝手な個人プロフィール再構成、ListenBrainzにない新規リスナー指標をsitewide APIから捏造すること、実績未検証の「ヒット確率」の表示。

## 6. 成功指標
週次取込成功率、遅延件数、スナップショットの一意性、曲同定率、トレンド計算可能率、前後期間の適合性検査成功率、説明文の根拠整合率。予測精度はPhase 4から測定。
